# 🚀 AUTO-MERGE: Автоматический мердж dev в main

## Описание
Единый скрипт для полной автоматизации процесса мерджа ветки `dev` в `main` с проверками, компиляцией и логированием.

**🆕 НОВАЯ ФУНКЦИЯ**: Автоматический коммит незакоммиченных изменений с перезапуском процесса мерджа!

## Использование

### Базовый запуск (рекомендуется)
```bash
./auto-merge.sh
```

### Опции командной строки

#### `--dry-run` - Только проверка без мерджа
```bash
./auto-merge.sh --dry-run
```
- Выполняет все проверки готовности
- НЕ выполняет мердж
- Полезно для тестирования

#### `--force` - Принудительный мердж
```bash
./auto-merge.sh --force
```
- Пропускает некоторые проверки
- Автоматически коммитит незакоммиченные изменения
- Используйте осторожно!

#### `--no-backup` - Без создания бэкапа
```bash
./auto-merge.sh --no-backup
```
- Ускоряет процесс
- Экономит место на диске

#### Комбинирование опций
```bash
./auto-merge.sh --force --no-backup
./auto-merge.sh --dry-run --no-backup
```

## Что делает скрипт

### 1. Проверки готовности
- ✅ Git репозиторий
- ✅ Текущая ветка (рекомендуется dev)
- ✅ Чистота рабочего дерева
- ✅ Существование веток dev и main
- ✅ Синхронизация с remote
- ✅ Различия между dev и main
- ✅ Возможные конфликты
- ✅ LESS компиляция
- ✅ Доступность remote

### 2. Автоматизация
- 🔄 **Автоматический коммит и перезапуск** - если есть незакоммиченные изменения, скрипт автоматически коммитит их и перезапускает процесс мерджа
- 💾 Создание бэкапа (если не --no-backup)
- 🎨 Компиляция LESS стилей
- ⚡ Компиляция JavaScript
- 📝 Коммит скомпилированных файлов
- 🔀 Мердж dev в main
- 📤 Пуш main в remote
- 🔙 Возврат на ветку dev

### 3. Логирование
- 📋 Подробный лог всех операций
- 🎨 Цветной вывод в консоль
- 💾 Сохранение лога в файл

## Файлы

### Выходные файлы
- `merge_YYYYMMDD_HHMMSS.log` - Лог операции
- `../backup_YYYYMMDD_HHMMSS/` - Бэкап проекта (если не --no-backup)

### Зависимости
- `package.json` - Должен содержать скрипты `less:all` и `js:build`
- `node_modules/` - Должны быть установлены зависимости

## Примеры использования

### Обычная работа
```bash
# Работаете в dev ветке
git add .
git commit -m "новый функционал"
git push origin dev

# Когда готовы к мерджу
./auto-merge.sh
```

### Быстрая проверка
```bash
# Проверить готовность без мерджа
./auto-merge.sh --dry-run
```

### Экстренный мердж
```bash
# Принудительный мердж с автокоммитом
./auto-merge.sh --force
```

## Безопасность

- ✅ Скрипт создает бэкап перед мерджем
- ✅ Все операции логируются
- ✅ Проверки предотвращают ошибки
- ✅ Автоматический откат при ошибках (set -e)

## 🆕 Автоматический коммит и перезапуск

Скрипт автоматически обрабатывает незакоммиченные изменения:

1. **Обнаружение изменений** - проверяет рабочее дерево на незакоммиченные изменения
2. **Автоматический коммит** - добавляет все изменения и создает коммит с временной меткой
3. **Пуш в dev** - пушит закоммиченные изменения в remote dev ветку
4. **Перезапуск процесса** - автоматически перезапускает скрипт мерджа
5. **Защита от циклов** - ограничивает количество перезапусков (максимум 3)

**Пример сообщения коммита:**
```
auto: автоматический коммит перед мерджем - Wed Aug 20 07:50:00 MSK 2025 - попытка 1
```

## Устранение проблем

### Ошибка "Git репозиторий не найден"
```bash
cd /path/to/your/project
./auto-merge.sh
```

### Ошибка "package.json не найден"
```bash
# Запустите из корневой директории проекта
pwd  # убедитесь что вы в capital-craft/
ls package.json  # проверьте наличие файла
```

### Проблемы с LESS компиляцией
```bash
npm install  # установите зависимости
npm run less:all  # проверьте компиляцию вручную
```

## Логи

Логи сохраняются в файлы с временными метками:
- `merge_20241201_143022.log` - для мерджа 1 декабря в 14:30:22

Каждая запись содержит:
- Временную метку
- Тип операции (INFO, SUCCESS, WARNING, ERROR, STEP, MERGE)
- Подробное описание действия
