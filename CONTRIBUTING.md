# Правила Внесения Изменений

## Модель Ветвления
1. Создавать рабочую ветку от `dev`: `feature/<краткое-описание>`.
2. Открывать PR: `feature/* -> dev`.
3. После merge в `dev` проводить проверку на subdomain.
4. Открывать PR: `dev -> main`.
5. После merge в `main` выполнять деплой в production.

## Правила
1. Не делать прямой push в `main`.
2. Все изменения вносить только через Pull Request.
3. Делать PR небольшими и сфокусированными.
4. Мержить только при зелёном CI.
5. Нестандартные технические решения фиксировать в описании PR.

## Проверка Перед PR
1. Выполнить локальную сборку:
   - `npm ci`
   - `npm run build`
2. Проверить, что секреты не попали в репозиторий.
3. Проверить, что поведение для окружений описано явно.

## Релизы
1. Для merge в production добавлять краткое описание релиза в PR.
2. Для значимых выпусков использовать теги (`vX.Y.Z`).
